### ✅ 2. HOSPITAL PASIR GUDANG — `DEMO-PG`

对照 `MR2607.1106` + `MR2607.1107`。两张单，其中**租金那张是 0.00**。

```
MR2607.1106  租金   MONTHLY RENTAL   3 @ 300 + 1 @ 300 + 1 @ 300 =  1,500.00
                    RENTAL WAIVE    -900.00 + -300.00 + -300.00 = -1,500.00
                                                          净额        0.00
MR2607.1107  表数   BLACK COPY   @ 0.0285   /   COLOUR COPY @ 0.285
                    BLACK COPY   @ 0.0190   <- 另一台机自己的价
```

这张单证明两件别的合约证不到的事：

- **黑白是按「价钱」合并的，不是按型号。** 六台机四个型号，黑白只印两行 —— 五台 0.0285 一行、
  一台 0.019 一行。按型号合会印四行，就错了。
- **一张净额 0.00 的单照样要开。** 前 12 个月全免，租金和 waive 一加一减刚好归零。

**核的过程抓到两个 UI bug**（都在 Meters & Pricing 的 Minimum / waive 那栏）：

1. 设「前 12 个月免费」，那栏写的是 `reach 0.00 -> waive 900.00` —— 一个没人设过的条件，
   而且 0 张也算达标。它只看用量目标，不看免费月数。**没条件的 waive**（引擎其实是每个月都减）
   也是同一句，一样反过来。现在按实际设的讲：
   `free for the first 12 months -> waive 900.00` / `every month -> waive 900.00`。
2. 同一行还挂着 `! rental is on its own invoice`。那句是给**要数张数**的 waive 看的 ——
   租金单上看不到张数，判不了。免费月份读日历，跟分不分单无关，现在不挂了。

两个都有 harness 守着：`testsilling-setup-summary`，六个 case。

### ✅ 14+15. FASTROCOM / TAG — `DEMO-F19`

两张单，`3000-F0019 INV 2607.pdf` 里的两份。**两个设定同时开到尽头**：
租金十台机合成**一个数**，表数**一台都不合**。

```
租金单   RA-10 UNIT   RENTAL - 07/2026    1 UNIT @ 5,097.00 =  5,097.00
表数单   十九行，每台机每个颜色一行                          = 10,008.94
           黑白 56,381 @ 0.026 = 1,465.90
           彩色 26,697 @ 0.32  = 8,543.04
```

三件这张单独有的事：

- **租金行的 Qty 是 1，不是 10。** 单价就是整组的钱。跟 MBJB（36 台 × 540）
  是相反的写法，两种都得印得出来。
- **租金行不印 `(n/36)`。** 他们印的是月份「RENTAL - 07/2026」。合约没有期数，
  系统就该什么都不印，而不是自己凑一个。
- **两台 4935I 的彩色表没动过，一台 IR1643IF II 根本没有彩色表。** 前者印零，
  后者不印 —— 十九行就是这样来的（九台有彩色 × 2 + 一台只有黑白）。

### ✅ 9. PUSPEN MUAR — `DEMO-PPM`

### ✅ 10. HOSPITAL TANGKAK — `DEMO-TGK`

五台机，**九张单** —— 这本资料夹里单最多的一个客户。

```
MR2607.1219  租金  3MB70006     769.50      MR2607.1413  表数  3MB70006      0.00
MR2607.1220  租金  3MB70008     769.50      MR2607.1414  表数  3MB70008      0.00
MR2607.1221  租金  4WE00869     769.50      MR2607.1415  表数  4WE00869      0.00
MR2607.1222  租金  3MB10304   1,406.00      MR2607.1416  表数  2GS03078     61.62
                                            MR2607.1417  表数  3MB10304    475.81
```

- **是 4 + 5 = 9，不是 5 × 2 = 10。** 2GS03078 没有租金，不该给它开一张空的租金单。
- **三张 0.00 的照样开。** 那三台免 5,000 张，各印了 3,502 / 4,018 / 1,783。
- **rebate 是先扣免费张数才算的**：10,623 − 5,000 = 5,623，再减 3%（168）= 5,455。

**核的过程抓到一个 bug**：「Meter FOC Qty」印的是**这个月用掉多少**（4,813），
不是**额度**（5,000）。这样等于跟客户说「你的额度就是你印的量」，而且每个月都不一样。
已改成印额度；顺带那行的 Qty 也从 1 变回 0（客户的单 Total Quantity 也是 0）。
梯子价的表没有额度栏，它的免费量是从 band 算出来的，那种继续印算出来的数字。

### ✅ 20. KENSINGTON GREEN — `DEMO-KEN`

十八台机，一张单，**只有三行**。

```
201-BK C+ P     BK COPY + PRINT A4&A3     45,959 @ 0.0245 = 1,126.00
223-COLOR C+ P  COLOR COPY + PRINT A4&A3   3,434 @ 0.3234 = 1,110.56
MIN 1764-12     MINIMUM RM 1764 OF COMMITTED MTH               0.00
                                          Net Total          2,236.56
```

- **保底那行是 0.00，但一定要在。** 客户承诺一个月印满 1,764，这个月印了 2,236.56。
  好月份把它藏起来，客户就只在被收钱的月份才发现有这条。

**核的过程抓到一个 bug**：Meters & Pricing 把**每台机都当成有租金**，
这张合约一台租金都没有却列了十八行 `Monthly rental 0.00`，footer 也算进去。
彩色那边同样：Tangkak 五台机只有两台有彩色表，之前列了五行。
现在的规则是**机器有那个表才有那一行** —— 要加租金就在上面打勾，下面立刻多一行。

**新的一样东西：2% meter rebate，扣的是张数不是钱。** 六台机一共印了 76,244，
实收 74,722，单上写 `Meter Rebate Qty (2%) : 1522`。

1,522 **不是** 76,244 的 2%（那是 1,524）。是每台各自算、各自去掉小数，再加起来：

```
25,777 -> 515      5,746 -> 114     22,053 -> 441
 5,272 -> 105      2,525 ->  50     14,871 -> 297     = 1,522
```

先加总再算 2%，发票会差两张纸。引擎本来就是逐台算的，这张单是守着它的。

另外两件：**六台抄表、五台有租金**（所以租金行 Qty 是 5），以及**有一个彩色表没动过**
（42 → 42），单上就没有彩色那行 —— 没用量不等于印一行零。

### ✅ 7. HOSPITAL SULTAN ISMAIL — `DEMO-HSI`

对照 `MR2607.1347`。一张单，四行，**14,211.89**。

```
RENTAL HSI - 13 UNIT MEDIUM DUTY        13 @   441.75 =  5,742.75
RENTAL HSI - 1 UNIT HIGH HEAVY DUTY      1 @ 1,377.50 =  1,377.50
METER CHARGE HSI - BK COPY + PRINT  106,960 @  0.0285 =  3,048.36
METER CHARGE HSI - BK COPY + PRINT  212,804 @  0.0190 =  4,043.28
                                          合计          14,211.89
```

第 3、4 行**字一模一样**，分成两行只因为价钱不同。按描述合、按型号合、按表种合 ——
三种都会印成一行 319,764 张，都错。规则是「一样价钱的才合」。

**这张单抓到一个真的算错**：合并行的金额本来是「每台各自算完再加」= 3,048.37，
但那一行印的是 `106,960 @ 0.0285`，客户自己乘出来是 3,048.36。客户的单也是 3,048.36。
已改：**一行只有一个价钱的时候，金额 = 数量 × 单价**；价钱不一样的合并行（blended）
照旧逐台加 —— 那种情况没有单一价钱乘得出来。

差别只有一分，但那一分客户乘不出来就会打电话。

## 三个月的资料 — 已经灌好了

`tests\seed-contracts\seed-three-months.sql`（可重跑）。**218 个 counter，2026 年 7、8、9 三个月。**

做法是把期初往前推两个月，让三个月接得上，而**九月的数字一个字都没动** —— 它是对照
PDF 的那一个月，不能为了做演示而移动。

```
MBJB001 BK   期初 109,865 → 七月 144,564 → 八月 179,263 → 九月 213,962
                    每一步都是 34,699
```

### ⚠️ 一定要照顺序开：**七月 → 八月 → 九月**

基准是「**上一张单开到哪里**」，不是「上个月的读数」。所以七月还没开的时候，
八月的基准还是期初 —— 会算成两个月的量：

```
先开七月              66,271.02  ✔ 跟 PDF 一样
没开七月直接开八月     104,457.04  ✘ 两个月的量
没开七八直接开九月     142,643.06  ✘ 三个月的量
```

三个月的用量一样，所以**照顺序开的话三张单金额一样**，随便拿哪一个月对 PDF 都可以。
